# Публикация результатов экспериментов генератором статических сайтов

Этот сайт — отчёт по заданию о генераторах статических сайтов (SSG) на Python.
Сайт собран MkDocs с темой Material из каталога `docs/` репозитория
[research-graph](https://github.com/bpa9008-prog/research-graph) и
автоматически публикуется в две площадки.

| Что | Где |
|---|---|
| Репозиторий | <https://github.com/bpa9008-prog/research-graph> |
| Сайт на GitHub Pages | <https://bpa9008-prog.github.io/research-graph/> |
| Сайт на Helios ИТМО | <https://se.ifmo.ru/~s566109/rg/> |
| Пайплайн | [`.github/workflows/site.yml`](report/pipelines.md) |

## Выбранные задания

| Раздел | Задание | Страница |
|---|---|---|
| Обязательная часть | Ход работы: сборка, CI/CD, базовый URL, лицензии | [Ход работы](report/setup.md) |
| Исследовательское | **T4.** Модель доставки и безопасность пайплайна | [T4](report/t4-security.md) |
| Практическое | **P4.** Развёртывание на Helios с контролем качества доставки | [P4](report/p4-helios.md) |
| Обязательная часть | Не менее трёх реальных ошибок с разбором | [Отладка](report/debugging.md) |
| Обязательная часть | Рекомендуемый стек и границы применимости | [Вывод](report/conclusion.md) |

Задания T4 и P4 выбраны парой: T4 разбирает риски способов доставки, P4
реализует один из них (SSH с отдельным ключом) так, чтобы эти риски были
закрыты на практике — проверка ключа хоста, разделение job сборки и доставки,
атомарное переключение версий, healthcheck и откат.

## Как устроена публикация

```text
push ─► build ─┬─► deploy-pages ──► healthcheck Pages
               │   (OIDC, pages: write)
               │
               └─► deploy-helios ─► healthcheck Helios ─► откат при провале
                   (SSH-ключ, known_hosts)

build: mkdocs build --strict, проверка «нет CDN», секретов нет
```

Каждая страница содержит метку сборки (подвал и `<meta name="rg-build">`):
по ней видно, из какого коммита собрана именно эта копия сайта.
