# Вывод

## Рекомендуемый стек

Для публикации результатов вычислительных экспериментов в учебном проекте
вроде research-graph (данные о репозиториях GitHub, таблицы, графики, немного
формул):

| Слой | Выбор | Почему |
|---|---|---|
| Генератор | MkDocs 1.6 + Material 9.7, версии закреплены точно | Markdown без обучения, сборка ≈ 0,5 с, поиск с русским стеммером, переопределение темы без форка |
| Формулы | MathJax 3 (вывод SVG) из репозитория | работает без CDN, нумерация и `\eqref` из коробки |
| Шрифты и иконки | системные шрифты, SVG-иконки темы | ноль внешних запросов, нет «пустого экрана» при сбое CDN |
| Основная площадка | GitHub Pages через `upload-pages-artifact` + `deploy-pages` | нет хранимых секретов, права только на публикацию |
| Отечественная площадка | Helios ИТМО: SSH, релизы, атомарное переключение | доступен без VPN, есть preview веток и мгновенный откат |
| Контроль | `--strict`, проверка внешних ресурсов, healthcheck с хешем коммита | ловит битые ссылки при сборке и «выложилось не то» после выкладки |
| Безопасность CI | actions по SHA, сборка без секретов, доставка без стороннего кода, `known_hosts` из проверенной переменной | ограничивает ущерб от supply-chain-атаки и подмены сервера |

## Когда рекомендация меняется

| Условие | Что меняется |
|---|---|
| Результаты получаются в Jupyter-ноутбуках и должны пересчитываться при сборке | Sphinx + MyST-NB или Jupyter Book: исполнение и кэширование ноутбуков встроены, у MkDocs такого нет |
| Нужны BibTeX-цитирование, нумерация рисунков и таблиц, ссылки на них | Sphinx (`sphinxcontrib-bibtex`, `numfig`) или Quarto. В MkDocs это плагины разной зрелости или ручная разметка |
| Нужна та же работа в PDF или LaTeX | Sphinx или Quarto: печатная версия из того же источника |
| Проект рассчитан на годы | следить за MkDocs 2.0: по заявлению команды Material он несовместим с текущими плагинами и темами. Версии закреплены, но долгосрочно это аргумент в пользу Sphinx |
| Сайт должен открываться в сети без доступа к GitHub | основной площадкой становится Helios или объектное хранилище, Pages — зеркалом |
| Ключ Helios нельзя доверить CI | Yandex Object Storage по S3 API с ролью только на один бакет: утечка ключа затронет сайт, а не аккаунт |
| Нельзя хранить секреты и ключ к Helios вообще | push только в GitHub, а на Helios сайт забирается по расписанию (`cron` + `git pull` + сборка на сервере). Доставка «изнутри», ключ не покидает сервер |
| Страниц с формулами мало, а вес первой загрузки критичен | MathJax подключать только на страницах с формулами или перейти на KaTeX (меньше, но беднее поддержка amsmath) |
| Хостинг не следует по символическим ссылкам | `HELIOS_MODE=swap`: переключение двумя переименованиями, вдвое больше места |

## Что сделано и что осталось

Сделано и проверено локально: сборка в режиме `--strict`, отсутствие внешних
ресурсов (в HTML и в браузере), все сценарии выкладки, отката, preview и
обрыва, healthcheck в положительном и отрицательном случае.

Осталось выполнить в вашем окружении и внести в отчёт: первый запуск
workflow на GitHub и Helios, скриншоты успешного и проваленного запусков,
времена доставки из сводки запуска (таблица в [P4](p4-helios.md)),
ошибки этих запусков в [Отладку](debugging.md#ci).

Следующее улучшение безопасности — ограничить ключ Helios одной командой
через `command=` в `authorized_keys` (см. [T4](t4-security.md#methods)).
